# report/

The build-and-check gate for the DNU-style report. Nothing here is part of the experiments.

| Path | What it is |
|---|---|
| `build_report.py` | Pure-Python helpers that check one requirement each: the nine-content-page limit, the required sections, a caption and a reference for every figure and table, every bibliography entry cited, the problems LaTeX reports in its log, and the polish checks below (layout warnings, template leftovers, title and abstract length, one file, one References heading). They need no TeX. |
| `gate.py` | The command-line wrapper: builds a report with pdflatex and bibtex, reads the text of every page with pdftotext, runs the helpers, and sets the exit status. |
| `make_numbers.py` | Writes `numbers.tex`: every number the report prints, as a key defined from the tracked result files (`phonebook/results`, the E4, E6 and E7 `protocol.json` files, the capacity and control books, the 126 `evaluation.json` files and three E7 `metrics.csv` files). |
| `numbers.tex` | Generated by `make_numbers.py`; do not edit. The report loads it with `\input{numbers}` and prints a number with `\num{key}`. |
| `check_text.py` | Mechanical checks on the prose of `main.tex`: every number comes from `numbers.tex`, and every claim paragraph carries its status words (see "Checking the prose" below). |
| `references.bib` | The report's bibliography: only the entries the report must cite (the anchor paper and AdamW), each copied from the arXiv page that was opened on 2026-11-19 and marked with a `verified` field (date and page; BibTeX ignores it). |
| `check_bib.py` | A strict reader and checker for `references.bib` (see "The bibliography" below). |
| `figures.py` | Draws the report's two results figures as vector PDFs into `figures/`: `fig_capacity.pdf` (capacity by width, with the E6 and E7 4,000-epoch rungs marked) and `fig_e7_curves.pdf` (E6 against arm W and arm S at widths 16, 32 and 64). |
| `figures/` | Generated by `figures.py`; do not edit. Include with `\includegraphics{figures/fig_capacity.pdf}`; each is at most 5.5 in wide, so no scaling is needed. |
| `template/` | The lab's report template, unmodified. The integration tests build it. |

Tests: `tests/test_report_build.py` (the helpers), `tests/test_report_gate.py` (the wrapper, and real builds of the template), `tests/test_report_numbers.py` (the numbers generator) `tests/test_report_figures.py` (the E7 table and the figures) `tests/test_report_bib.py` (the bibliography checker, the pinned entries and a real BibTeX build) and `tests/test_report_text.py` (the prose checks).

## The bibliography

```bash
python -m report.check_bib report/references.bib                        # check the file
python -m report.check_bib report/references.bib --tex report/main.tex  # also: every entry cited, every citation has an entry
```

Exit status: 0 no problems; 1 problems (one line each, "key: what is wrong"); 2 a file cannot be read. The reader is strict: anything it cannot parse is an error with a line number, never skipped (`@string`, `@preamble`, `#` concatenation, bare words as values and parenthesis-delimited entries are refused). Each entry must be an article, inproceedings or misc with its required fields and only known field names, authors as "Last, First" with every author listed, the title in one brace group (so BibTeX keeps its capitals), a year from 1900 to 2026 that matches the year in the key, ASCII text, and a `verified` field "YYYY-MM-DD, https://..." naming the page that was opened. An entry with an `eprint` must also have `archiveprefix`, `primaryclass`, a `url` that is its arXiv abstract page and (misc) `howpublished` "arXiv preprint arXiv:<id>", and the identifier must have the right number of digits for its month.

`tests/test_report_bib.py` pins the two committed entries to literals copied from the opened pages, so changing a verified field fails a test until someone opens the page again, and builds a tiny document with real `pdflatex` and `bibtex` (style `plainnat`) to check that BibTeX accepts the file without a warning and prints both references exactly. Add an entry only when the report cites it: an uncited entry fails the gate (G6). Use `\citet{...}` and `\citep{...}` (natbib, loaded by `dnu.sty`).

## The figures

```bash
python phonebook/report_e7_curves.py --out phonebook/results   # write fig_e7_curves.csv (the table behind the curves figure)
python -m report.figures --out report/figures                   # write the two PDFs
```

Both refuse to overwrite an existing file unless `--force` is given; exit 1 with `error: ...` when an input is missing or inconsistent. `fig_e7_curves.csv` has one row (`arm,model_d,entries,seed,epoch,recalled`) per logged epoch of each of the 27 runs: the 9 E6 runs at widths 16, 32 and 64 and the 18 E7 runs (arm W and arm S, three widths, three seeds); the E6 rows equal the rows of `fig_e6_curves.csv` at those widths. A run whose `protocol.json` does not match its folder name (arm, width, 4,000 epochs, weight decay or step schedule) is refused.

- **Curves figure.** Mean of the three seeds at each logged epoch, with the lowest-to-highest band; the y axis starts at 90%. The one dip after settling (the fewest entries recalled after a run first held 100% for 50 logged epochs, the report's `e7w.dipmin` rule) that the axis cuts off, arm W at width 64 down to 25 of 640, is written on the panel. Dashed line: arm S's step-down at epoch 2,000.
- **Capacity figure.** E4's capacity at each epoch budget (blue ramp) and the 4,000-epoch rung of E6 (gray), arm W (orange) and arm S (green), marked passed or not passed from `e6_extension.json`, `e7w_extension.json` and `e7s_extension.json`. E6 has a mark for a rung that did not pass (width 64, 640 entries); the figure has none for a failed E7 rung, so it refuses to draw one instead of leaving it out. The three arms sit side by side at each width; their positions are an offset in points, so the data values are exact.
- **Format.** TrueType fonts embedded (`pdf.fonttype 42`, never Type 3), no creation date, all text at least 8 pt, width at most 5.5 in. Rendering the same data twice gives the same bytes on one machine; another matplotlib version may differ in bytes, so regenerate with `--force` after upgrading and read the result.
- **Checks.** `tests/test_report_figures.py` recomputes the table from the raw `metrics.csv` files without using the code under test, compares every plotted value with the table, ties the pass flags to the raw curves, and ties the dips to `numbers.tex`.

## The numbers file

The report text never types a result. It says `\num{e7w.bits.w64}`; the key is defined in `numbers.tex`, which `make_numbers.py` writes from the tracked result files. Keys are lower-case words, digits and dots (`e4.cap.w64.b1000`: E4 capacity, width 64, budget 1000). An unknown key is a LaTeX error (`Package numbers Error: Undefined number key`), which the gate reports, never a blank.

```bash
python -m report.make_numbers            # write report/numbers.tex
python -m report.make_numbers --check    # write nothing; exit 1 if the committed file differs from what would be written
```

Exit status: 0 written or up to date; 1 with `--check` and the file differs or is missing; 2 an input is missing, malformed or inconsistent (or the output cannot be written). The generator refuses anything that is not a whole number where a count is expected, any file that disagrees with another, and any curve with a missing or repeated logged epoch; it never prints 0 for a value it could not read. `tests/test_report_numbers.py` checks every key three ways: against literals typed from the verified recompute of 2026-11-18, against an independent recompute from the raw per-run `metrics.csv` files, and against the committed `numbers.tex`.

`typed_numbers_matching(tex, values)` lists decimals and numbers of three or more digits typed in the prose that equal a generated value: use it on `main.tex` to find a result typed by hand.

**Key families for the Experimental design section** (R5; 36 keys, 304 in all). The rules the keys state are constants in `make_numbers.py` that the code also applies, so a key cannot differ from the rule in force; the tests compare them with the locked scorer (`phonebook/score_e7_predictions.py`), the spec text and the generator of the phone book.

| Family | Says | Checked against |
|---|---|---|
| `design.phone.area`, `.exchange`, `.subscriber` | the phone-number space: 800 area codes, 800 exchanges, 10,000 subscriber numbers (`design.bitsentry` is the log2 of their product) | every entry of the 905-entry book of each seed |
| `design.hold.min`, `.window`, `.from` | "holds": at least 50 of the last 100 logged epochs, the window starting at epoch 3001 | the locked scorer's `HOLD_MIN`, `LATE_LOGGED` and `LATE`; the epochs and the logging interval |
| `design.settled.logged`, `.epochs` | "settled" (the dip rule): 50 consecutive logged epochs at 100%, which is 500 epochs | the logging interval |
| `design.rule.min` | seeds out of 3 that must be perfect for a rung to pass (2) | the locked scorer's `PASS_SEEDS`; every extension file |
| `design.budget.1` to `.4` | the four E4 budgets (100, 300, 500 and 1000 epochs) | the budget keys of `e4_capacity.json` |
| `design.rung.first`, `.last`, `.count`, `.ratio.min`, `.ratio.max` | the ladder of nested books: 10 to 905 entries, 14 rungs, neighbours 1.40 to 1.43 times apart | the protocols and the book files of every seed |
| `design.control.max`, `.runs` | the most control entries recalled in any run (0) and the runs inspected (126) | the four cells files (one row per run, every `control_ok` True) |
| `design.runs.e4`, `.e6`, `.e7` | runs per experiment (96, 12, 18) | the protocols |
| `design.regen.agree`, `.runs` | runs whose regenerated answers equal the teacher-forced count of the saved weights (126 of 126) | every `*.evaluation.json` |
| `e6.next.*`, `e7.next.*` | the next rung on the ladder above each pass (`none` where E6 did not pass or at the top) | the ladder |
| `e6.updates.*` | updates in 4000 epochs at the E6 rung of each width (updates per epoch times 4000) | the protocols |

## Checking the prose

```bash
python -m report.check_text report/main.tex           # while you write
python -m report.check_text report/main.tex --final   # before submission: every claim must be marked
```

Exit status: 0 no problems; 1 problems (one line each); 2 the file cannot be read or the numbers cannot be built. It builds the numbers from the repository (as `make_numbers` does), so it needs the tracked result files.

**Numbers (IC-1).** A problem is an undefined `\num{key}` and a number typed in the prose that equals a generated value (three digits or more, or a decimal point; small whole numbers such as widths and seed counts are structure). It says which key carries the value: `the number 905 typed in the text equals a generated value (e7.next.w64): write \num{e7.next.w64}`. Printed as notes, never as problems: other numbers typed in the prose (read them yourself) and how many keys nothing uses. In TeX a percent sign is written `\%`; an unescaped one starts a comment, and everything after it on the line is not prose.

**Claims (G7).** Put a marker comment on the line above each paragraph that states a claim of the accepted ledger (v2, 2026-11-13), with a blank line before it:

```tex
% claim: CL-4
The claim that a wide model keeps ... was Not true in E6 ...
```

The paragraph, up to the next blank line, is checked: case, markup, line breaks and hyphens do not matter, and comments and the arguments of `\cite`, `\ref`, `\label` and `\num` are not read. A marker may name several claims (`% claim: CL-2, CL-3`) and markers may be stacked. Text outside marked paragraphs is not checked; "no stronger than the ledger" stays a human read.

| Claim | Must contain | Must not contain |
|---|---|---|
| CL-1 | Established | can store; has a capacity of |
| CL-2 | Supported; not shown for width 64 | established; shown |
| CL-3 | Established | holds; keeps |
| CL-4 | Not true in E6 | cannot hold |
| CL-5 (the limit sentence) | Not established | |
| CL-6 | lower bound | |
| CL-7 | Supported | established |
| every claim | | prove (proves, proved, proven, proof); impossible; optimal; guarantee |

"Not established" never counts as "Established" (nor do "never established", "not yet established" or "isn't established"), and "not shown" is fine where "shown" is forbidden. The words are the ledger's status words and its "Do not say" items that a program can check; change the table in `check_text.py` only with a decision about the ledger.

## Run the gate

```bash
python -m report.gate report/main.tex
```

It builds into `report/build/` (git ignores `build/`), runs pdflatex until the `.aux` file stops changing (bibtex once, when the document has a bibliography), and prints where the content ends and where the References heading is. Pass `--out DIR` to build somewhere else.

| Exit status | Meaning |
|---|---|
| 0 | every gate passed |
| 1 | the gate ran and found problems; each is printed (a build that produced no PDF counts) |
| 2 | the gate could not run: a tool is missing or did not finish, or a file or folder cannot be read, created or removed |

The page limit is measured two ways that must agree: the page that `\label{endcontent}` lands on, read from the `.aux` file, and the first page whose text has a line that is exactly `References`, read with pdftotext. Put `\label{endcontent}` as the last token of the last content paragraph (the Acknowledgments paragraph if there is one). The References heading may be on the same page as the label or on the next one; if it is on the next page, nothing may sit above it there, because text above it means content continues after the label and the label is too early. The checks read the main `.tex` file only; files it pulls in with `\input` or `\include` are not followed, so any of them except `\input{numbers}` is itself a problem (see below).

## What else the gate checks

After the checks above, `gate.py` runs `build_report.polish_problems` on a build that produced a PDF. Each problem is one line of the report.

| Check | Problem it prevents | Rule |
|---|---|---|
| layout warnings in the log | a figure or long URL running into the margin, a missing glyph, a substituted font, a float taller than the page | an `Overfull \hbox` or `\vbox` of more than 1 pt (raise the limit with `--max-overfull PT`), any `Missing character`, any `LaTeX Font Warning`, any `Float too large for page`. Underfull boxes are ignored (`dnu.sty` sets `\sloppy`). |
| template leftovers | a PDF that still says "Author Name", "DNU Research Report Title", the template's instruction sentences, or a heading ending in "(optional)" | read from the text of the PDF pages, line breaks and the typographic apostrophe ignored |
| title and abstract length (RP-08, RP-09) | a title outside 8 to 15 words, an abstract outside 150 to 200 | counted in the source: `\num{...}` and a citation are one word each, inline math is one, braces and commands vanish, `~` is a space, and a token needs a letter or digit |
| one file | captions, citations and headings in another file escaping the checks above | any `\input`, `\include`, `\InputIfFileExists`, `\subfile` or `\import` except `\input{numbers}` |
| one References heading | a manual `\section*{References}` next to `\bibliography` printing the heading twice | counted in the PDF text; `pdftotext` may join two headings into one line, which counts as two |

Use `\bibliography{...}` without a manual `\section*{References}`: natbib prints the heading. The template's own `\section*{References}` is for a hand-made list.

## Needs TeX

pdflatex, bibtex and pdftotext must be on PATH. MiKTeX provides all three (`winget install MiKTeX.MiKTeX`, then open a new terminal so that PATH is refreshed). The three real-build tests in `tests/test_report_gate.py` are marked `integration` and **fail**, they do not skip, when TeX is missing, so a green full suite means the report really builds here. `python -m pytest -m "not integration"` leaves them out.

A report that uses a package MiKTeX has not installed yet can stop at MiKTeX's install prompt, which the gate cannot answer; the gate gives up after 300 seconds and says so. Build once by hand in `report/` (`pdflatex main.tex`), let MiKTeX install the package, then run the gate again.
